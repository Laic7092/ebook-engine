# 中文文本政策（`TextRules`）

`TextRules` 控制三件事：**成对标点挤压**、**行末标点悬挂**、**中西文自动间距**。
它挂在 `ComputedStyle.text.rules` 上，是排版输入的一部分，不属于 IR 字节流
（`LayoutResult` 里没有它，旧 golden 原样解码）。

```rust
pub struct TextRules {
    pub spacing_trim: bool,
    pub hanging_punctuation: bool,
    pub autospacing: bool,
}
```

字段是 `#[serde(default)]`，零值 = 全关。实现分层如下：

- **机制** 在 `crates/ebook-layout/src/punct.rs`：分类、成对挤压、悬挂、自动间距。
  这个文件里**没有任何具体文字**，每个函数都要传入一张 `&PunctTable`。
- **数据** 在 `crates/ebook-layout/src/typography.rs`：字符类表、可压/可悬集合、
  比例、以及分页的孤寡修复优先级。按 `meta.lang` / `lang` 属性选档案。
- 逐个开关的测试在 `crates/ebook-layout/tests/punct.rs`。

新增一门语言只加一个 `static`，不动机制层；详见
[design.md §11.5](design.md#115-版式档案机制不认识语言)。

---

## 1. 三个开关的出处

| 开关 | 对应规范 | 本引擎实际实现的可判定部分 |
|---|---|---|
| `spacing_trim` | CSS Text Module Level 4 §8 `text-spacing-trim`；CLREQ §6.3.2「标点符号的宽度调整」；JLREQ §3.1「句読点・括弧類」 | 相邻标点对只压**拥有空白半边**的那一个；只压实测会被浏览器压掉的引号类（`trimmableOpening` / `trimmableClosing`） |
| `hanging_punctuation` | CSS Text L4 §9 `hanging-punctuation: allow-end`；CLREQ §6.1.3「行尾点号悬挂」；JLREQ §3.2「行末の句読点」 | 行末标点最多探出半宽；只放宽 fit 判定，不移动字形坐标。**悬挂集合按档案分**：通用档案含闭括号/闭引号，简体中文档案只含点号类，且连续标点不悬挂 |
| `autospacing` | CLREQ §6.3.3「横排的中西文混排配置」建议的 1/4 em 空隙（**不是** CSS 初始值） | 表意字符 ↔ 拉丁字母/数字之间加 1/4 em；挂在左簇上，行末收回，不插行首行尾 |

规则表照抄规范里**成对可判定**的部分；需要上下文（前后若干字、段落语言、
字体是否有半宽字形）的规则明确不装，见第 4 节。

标点分类来自 CSS Text L4 §8.2 的字符类，另加 `U+2018/2019/201C/201D` 四个中文
对话实际使用的弯引号（规范列表里没有，但浏览器会压）。全角括号、顿号、间隔号
都不在“可压”集合里，与 `~/layx/render/punct.go` 的观测结果一致。

## 2. 为什么默认全关

1. **零值 = 规范默认。** `TextRules::default()` 是 `false/false/false`，
   与 `TextStyle` 其余的 `#[serde(default)]` 字段同一约定：旧数据、旧宿主、
   手搭的测试文档都不需要知道这三个开关存在。
2. **这是文档政策，不是正确性。** 同一段中文，压不压标点、要不要悬挂，取决于
   书籍的版式设计（正文 / 诗歌 / 报纸窄栏），不是引擎能替作者决定的事。
3. **格式层还没有解析这些 CSS 属性。** `text-spacing-trim` /
   `hanging-punctuation` / `text-autospace` 目前不会被 `ebook-format` 读进
   `ComputedStyle`；开关由宿主在构造 `StyledDoc` 时显式设置。默认关掉可以
   避免“引擎偷偷改宽度”，也让 golden 与像素基线不依赖浏览器对这几个属性的
   默认值。
4. **golden 的可比性。** 默认关意味着 `StubMeasurer` + 纯文本路径的字节输出与
   加政策之前完全一致；政策只在显式打开时改变行宽。

## 3. 推荐开关组

| 场景 | `spacing_trim` | `hanging_punctuation` | `autospacing` | 说明 |
|---|:---:|:---:|:---:|---|
| 中文正文（默认推荐） | ✅ | ✅ | ✅ | 最接近中文纸书：引号成对压半宽、行末标点不孤零零掉下去、中西文之间留气口 |
| 中文正文（保守排法） | ✅ | ❌ | ✅ | 不想让标点探出版心时关掉悬挂；其余两项不改变字面宽度分布 |
| 窄栏 / 报纸 / 多栏 | ✅ | ✅ | ✅ | 悬挂能明显减少“行末只剩标点”的孤行 |
| 诗歌 / 代码 / 表格 | ❌ | ❌ | ❌ | 保留作者输入的字距与对齐意图 |
| 纯西文 | ❌ | ❌ | ❌ | 三个开关都不该影响拉丁文本；打开也不会有可观测变化 |
| 竖排（未实现） | — | — | — | 字段保留，纵向布局不在本轮 |

打开顺序没有依赖：三个开关各自独立结算，可以只开一个。

## 4. 与浏览器的已知差异

| 差异 | 本引擎 | 浏览器 |
|---|---|---|
| 可压标点集合 | 只压引号类（`trimmableOpening/Closing`） | 取决于字体是否有半宽字形与 `text-spacing-trim` 支持；全角括号在部分引擎会被压 |
| `text-spacing-trim: space-first` / `trim-all` | 不支持 | 新规范里有；本引擎只有“成对挤压”这一档 |
| 行末悬挂 | 最多探出**半宽** | `allow-end` 允许整字探出，且与 `text-wrap` 交互 |
| 自动间距位置 | 只在表意 ↔ 拉丁/数字之间，1/4 em，行末收回 | `text-autospace` 还管标点前后、行首行尾、`ideograph-alpha` 等多个子项 |
| 挤压时机 | 断行**之前**改簇宽，量到的宽度就是画出来的宽度 | 多数引擎在字形阶段做 `halt`/`palt`，行宽与墨迹可能不同步 |
| 上下文规则 | 不做（避头尾只认 UAX #14 的成对规则，悬挂只放宽 fit） | 有完整的避头尾与标点挤压上下文 |
| 与 `letter-spacing` 的关系 | 先整形、再叠加字距、最后做挤压/自动间距 | 各引擎顺序不同，结果可能有零点几像素差 |
| 与字体的关系 | 不查询字体的半宽字形，宽度完全由 `TextMeasurer` 决定 | 字体缺半宽字形时挤压可能失效 |

这些差异意味着：**同一份 XHTML 在浏览器与引擎里的断行位置可能不同**。这是
预期行为——引擎的承诺是“同一份 `StyledDoc` + 同一份字体字节 + 同一组开关，
输出逐字节确定”，不是“像素级复刻某个浏览器”。

## 5. 实现要点（给改这一层的人）

- 挤压与自动间距在**断行之前**写进簇宽，并把差值写回簇末字形；否则
  “量到的宽度”与“画出来的宽度”会分叉。
- 悬挂**只放宽 fit 判定**：行盒右边界可以探出，但字形坐标不动，所以后端不需要
  知道悬挂存在。
- 自动间距挂在**左簇**上；行末的最后一簇收回空隙，不把 1/4 em 留在行尾。
- 所有规则都是成对/单字符可判定的（无回溯、无上下文窗口），因此乱序并行排版
  仍逐字节相同。
- `TextRules` 不进 IR：改政策只改变 `LayoutResult` 的几何，不改变字节布局，
  major/minor 都不需要动。
- **分类表要包含悬挂表里的所有点号**。孤字判定查的是分类表（`class_of`），悬挂查的
  是悬挂表（`hang`）——两张表各写各的，`！`/`？` 一度只在后者里，于是「……呢！」
  这种末行永远不算孤字。现在 `punct.rs` 的测试直接钉住这一条。
- **行末标点的挤压优先于悬挂**：压进版心比探出版心更像纸书。只有挤压也救不了才挂。
- 孤字修复有两条路（`fix_orphan`）：往下挪**一整块**（从最近的合法断点开始，常常是
  「字 + 标点」两个字），或者把整个末行压进上一行（`shrink_line`，靠字缝的收紧
  容量）。只挪一个字在标点结尾的段落上会被行首避头尾挡住，结果是什么都不做。
